## 我自己做的取舍（不算问题，留档备查）

- **dockview 8 的 React 绑定是单独一个包**（dockview-react），需求表里只写了 dockview。两个都装，版本相同。
- **shadcn/ui 按 Tailwind 4 对应的 new-york-v4 registry 生成**，底层是统一包 radix-ui；sonner 组件原本从 next-themes 取主题，改成读 html[data-theme]（只改取主题的地方，其余照原样，也没多装 next-themes）。
- **shadcn 的侧栏是 fixed + h-svh**，而原型是带外边距的窗口：给窗口加 transform 让它成为包含块，并用 CSS 把高度改成 100%。
- **2000 轮的对话不预生成**：第 i 轮由固定种子按 index 现算，翻到哪页算哪页；时间戳固定，所以截图和测速可重复。
- **Virtuoso 的「滚到底」会比 DOM 少约 66px**（它自己的高度模型没跟上最后一条的真实高度）。处理办法：首屏在 rAF 里直接盯着 scroller 钉底，连续 3 帧贴住底才打 turns:painted；之后继续钉到稳定。
- **卡片在真实协议里怎么下发没查到**，types.ts 里标「未核实」；引用片同一条 item 上的 textElements 也标了未核实。
- **流式事件名未核实**：本地模拟用 item/started、item/delta、item/completed、turn/completed，接真接口时要对齐。
- **多线共用的路段**：数据上仍是一条连线（检查、汇合、排版都按一条算），带 lineIds 说明哪几条价值流共用它；画的时候每条线各画一条并排的（4px 线、6px 间距），共用站画成中性跨线胶囊，共用门画成跨线中性菱形；站 / 门 / 池 / 起终点一律「浅底深描边」，线色只留给线（brief §四.2，用户 2026-10-28 确认）。
- **地铁线「≥4 条线时，点图例里的一条线，其余淡到 25%」暂不实现**：第 1 期现有流程最多 3 条线，没有触发的场景；协调线 2026-10-28 同意先登记，等第 2 期有 4 条线的数据再落（perf 报告备注里也写了）。
- **画布缩放下限 0.92**：站名 15px、副标 12px，缩到 0.92 时是 13.8px / 11px，满足「站名 ≥12px、副标 ≥11px」；再小就不缩了，靠横向平移看。
- **「策略」改叫「流程」**：用户 2026-10-27 裁定，界面文案全部改成「流程」，代码标识用 flow，路由是 #flow:<id>；原型的 v0 文件名不改。
